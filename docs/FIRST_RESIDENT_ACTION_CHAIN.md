# 造造 × 苹果｜V10.6 动作预览

普通苹果仍由探探优先发现，造造沿世界任务实际走到互动格后才负责提出普通苹果的下一用途。实际 `reaction` 触发 Inspect，完成该片段后，在当前互动和提议仍有效时播放 Think。造造按居民格到苹果格重新求朝向，动作帧跟随既有地图脚点与深度。用户确认后，如果造造离开，会按原寻路走到一个不会被下一形态占用的苹果互动格；抵达才播放 Build。Build 结束再次由 Bridge/World 验证占地并提交。成功才替换苹果 Sprite，并在同一世界落点叠加成长 FX。后续巨型苹果到苹果屋、叶子跨地形沿用原确认和迁移。

播放中的请求只在内存。Escape 可取消未完成的改造，重置或刷新不写成功事件。动画完成后的校验失败保持苹果原样和提议，居民回到探索。动作片失效时保留原方向 Sprite、世界目标轮廓与说明；FX 缺失用同锚点短提示。减弱动态偏好使用稳定的代表帧。

本轮为技术动作预览。身体帧、意图符号、目标轮廓与文字足以辨别当前阶段。手部接触、工具操作、材质形变和表现性动作尚需正式美术。

## 注册结构

- **Action Registry** 由 `dist/resident-actions.js` 中的 `actions` 提供。记录动作 ID、帧数、帧间隔、文字。当前兼容统一 48×48 四向行与脚点 (24,40)。扩展时把 residentId、sheet、方向映射、origin 和循环策略列入条目。
- **Object Interaction Registry** 对应 `interaction`。匹配居民、物件类型、下一形态。扩展时登记真实触发事件、候选互动格规则、动作序列和取消条件。物件原 footprint 与用途合法性继续由 World 和 Bridge 管理。
- **Evolution FX Registry** 对应 `fx`。登记效果资源、帧数、帧间隔、目标锚点与相对层级。扩展到苹果屋及叶子船前先校准建造正面与下水着点，保持效果仅在成功后播放。

## 动作缺口

- **探探** 现有四向静帧与步进摆动。候选 Inspect / Think / Build 均为技术帧，尚需正式 Idle / Walk、主动俯身观察、采集或递物、Rest 和 Celebrate。
- **造造** 已接入技术 Inspect / Think / Build。尚需正式 Idle / Walk、对齐手部触点的 Inspect、可识别的研究姿势、手臂和工具 Build、Rest 和 Celebrate。
- **慢慢** 现有四向静帧和互动体高变化。候选 Inspect / Think / Build 未接入。尚需正式 Idle / Walk、慢动作触碰、坐下/起身与设施依靠、Rest 和 Celebrate。

可直接继续用独立 Growth FX、意图标记和原足点规范做技术验证。正式角色动作和接触表演需重新制作，天气与岛屿簿进入下一阶段。
