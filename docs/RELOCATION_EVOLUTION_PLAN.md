# 跨地形演变方案｜陆地树叶到水中叶子船

## 现有能力

- **不同地形类型部分支持。** `objects.json` 以物件类型描述 footprint、互动偏移与 `allowWater`。`checkPlacement` 支持全水域的漂浮占位。校准页有可漂浮的 leaf-boat 定义，正式世界未注册它，且 `allowWater` 允许水域同时也允许适合放置的地面，表达不了“仅水域”。
- **重新选址缺失。** 现有 `World.evolve(id)` 总是在旧 `object.at` 校验下一形态并执行。仅加入 `leaf → leaf-boat` 映射无法完成从陆地换到水域。
- **新占地、身份、失败回滚已有基础。** `checkPlacement(at,type,replace)` 可在任意候选坐标计算下一形态并排除旧实例。当前成功演变保持实例 id 与 collectionId，失败在修改状态前返回。需扩充连通性验证，明确源格释放、目标格占用属于同一次动作。
- **迁移事件缺失。** Bridge 的现有确认、演变事件记录形态，没有迁移坐标。Store 已可一次提交世界、条目、事件；不需要另建存档系统。

## 最小流程

1. 在正式物件表加入叶子船及下一阶段映射，提供显式水域限定例如 `placementSurface: 'water-only'`。继续以 footprint、`floating` 和互动偏移描述占位及岸边可达性。先确认校准中 31 px 船身是否允许越格，再选单格或多格水域占地。避免用同一个材质属性兼做可走判定。
2. 在用途提议中标记该变形需要重新选址。玩家按「选择水岸位置」后，复用 World 落点预览和取消入口，载入船形 ghost。期间保留陆地叶子、实例 ID 和旧碰撞。可点击查询水域原因。关闭、切换岛屿和取消都不移动旧实例；刷新可回到仍待处理的提议。
3. 给 World 增加兼容现有调用的 `evolve(id, targetAt = object.at)` 入口或单独事务方法，二者复用一个提交校验。预览与确认都传目标坐标和旧实例。最后一次检查必须覆盖水域完整性、漂浮占位、现存物件、居民下一步、现有入口和至少一个可达岸格。比较真实“迁移前”连通性与目标快照。迁移前包含旧占地，目标快照只释放旧格并应用目标占位。现有苹果原地流程继续用当前默认路径。
4. 通过后才停止旧探索，更新同一对象的 `type/at/floating`，刷新画面并重排路径，提交 Store 条目的 `form/at/proposal` 和世界快照。使用原 collectionId、sourceId 与 captureId 链路。若任一校验失败，保留旧形态、旧格、旧碰撞、原历史和待处理提议，不写成功确认。
5. 成功提交 `USE_CONFIRMED`、`OBJECT_TRANSFORMED`，同事务增加 `OBJECT_RELOCATED` 或在演变事件上同时记录 `fromAt/toAt`。用实例 ID 加来源形态构造稳定事件 ID，让重试或双击不产生重复记录。新地点由真实探索产生到达与互动事件。

## 实施优先级

- **P0 · 市集前。** 保住苹果完整链路和取消/重复确认行为。用本轮热图找一小片低风险前庭，挑若干未开放的宽地格单独提高放置许可。保留出生点周边、桥口、正门、湖岸通路和窄道。为新增格重跑苹果三态、点位阻断、非法回退、东扩和刷新。展览脚本保持一条可重复的 Story Land 示范路径。
- **P1 · 有余量再做。** 叶子船仅实现最小重新选址、原实例迁移、失败回滚及 Memories，利用已存在的候选 Sprite；搬运动画另排。增加确定性的居民偏好权重及同分回退，小步验证对当前任务连贯性的影响。对全员错过入口的活物增加有限重试与明确状态。
- **P2 · 推迟。** 全岛自动开放、动态导航大改、多对象跨地形批量搬运、完整搬运动画、复杂角色长期目标和 AI 决策。先取得展览现场反馈再排优先级。

## 验收建议

覆盖地面选址、水深无岸点、多个船占位冲突、源与目标复用、居民下一步占用、迁移取消、失败后重试、同一实例与事件链刷新恢复。独立保留苹果固定锚点的成功/失败回归。
