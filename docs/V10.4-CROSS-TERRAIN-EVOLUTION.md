# V10.4 叶子船跨地形演变

基于 `cc36a86`，开发分支 `feature/v10.4-cross-terrain-evolution`。在 Observer 目录执行 `npm run build` 与 `npm run preview`。

## 运行路径

1. 按 T 接收本地演示照片，从 Collection 的 Discovery Pocket 选叶子，放在 Story Land 陆地 (19,16)。
2. 造造借研究偏好优先探索，到达叶子互动格后提出制作小船。可暂不改变，或打开提议并选择水岸位置。
3. 选址期间仍显示陆地原叶。粉色表示拒绝，薄荷绿表示可确认。陆地 (19,16) 被拒绝，深水 (7,11) 缺少可达岸点，(9,12) 右侧覆盖格不是水。合法示例为 (8,12)，占用 (8,12) 和 (9,12)，互动点在岸上 (10,12)。
4. 确认入水后，陆地占地释放，同一实例变成漂浮叶子船。造造沿原有寻路前往岸边。Memories 的真实事件显示用途确认、演变、迁移坐标和到岸互动。

## 规则与数据

- `objects.json` 正式登记既有 44×41 PNG，声明 `water-only`、两格横向 footprint、接地点与六个岸侧候选点。船只参与物件占用，水域仍不可行走。校准页复用正式定义。
- 叶子只在陆地形态产生跨地形提议，原先水面可放叶子的规则仍有效。World 用同一校验检查完整水域、重叠、居民位置、连通性及可达岸边。预览排除原物件的旧占地作假设校验，场景不会提前移除原物件。
- Bridge 提交带目标坐标的世界快照、Collection 形态、原 sourceId 和三个成功事件。`USE_CONFIRMED` → `OBJECT_TRANSFORMED` → `OBJECT_RELOCATED`。迁移事件保留 `fromAt/toAt`。保存成功才应用迁移，存储拒绝时保留原物件、提议与历史。
- 暂不改变、取消、非法目标、储存失败，以及选址中刷新都保留原叶。未完成草稿不进入存档。成功后既有实例 ID、原始照片和事件链保留，重复确认不会创建新实例。
- 苹果仍原地演变，现有 World / Collection / Memories、Phaser 单实例和 CRT 沿用。
